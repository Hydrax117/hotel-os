### Retry state machine

The prior retry handler set `loading: true` and cleared `error` outside the effect, which caused the component to re-render into the loading skeleton with the effect never running. The fix moves all state resets into the effect itself (already there: `setLoading(true); setError(null)` run at the top of the effect body), and the handler simply increments `retryCount`. Since `retryCount` is in the dependency array, the effect fires. The `setPage(1)` in the handler also remains, resetting pagination before retry.

### searchHotels auth removal

`apiClient` is gone from the import list in `search.ts`. `searchHotels` now calls `fetch` directly against `BASE_URL`, identical to `serverFetch` except it runs in the browser and adds structured error body extraction. The error path tries to parse `body.message` (NestJS validation errors return an array here) and joins it into a readable string. This is strictly better error reporting than the prior `apiClient` path.
