# Traveler homepage implementation

Traveler-facing homepage with all seven sections, responsive across breakpoints, zero TypeScript errors in build. Design tokens, client/server boundaries, and prop types all meet spec. One type issue in `layout.tsx` is the only blocking concern.

**Watch for:** `LayoutProps<"/">` in `layout.tsx` is not a valid Next.js type — confirmed. TypeScript accepts it as an unresolved generic (so the build passes), but it's not what's intended. The correct fix is `{ children: React.ReactNode }`.

**Verdict**: NEEDS_CHANGES

## High-level view

The layout file references `LayoutProps<"/">`, a generic form that Next.js's `LayoutProps` type doesn't support. The framework defines `LayoutProps` with `params` and `searchParams` fields — no route-string generic. TypeScript silently accepts unresolved generics rather than raising an error, so this slips through the build check. The layout doesn't use params or searchParams, so the correct type is `{ children: React.ReactNode }`.

All other criteria pass: build succeeded with zero errors, all seven sections present and in order, client/server boundaries correct, no `any` types, `--tp-*` tokens added cleanly alongside existing `--ob-*` and `--db-*` tokens, mobile hamburger and collage placeholder both present.

## LayoutProps type misuse in layout.tsx

`layout.tsx` declares the props parameter as `{ children }: LayoutProps<"/">`. Next.js exports `LayoutProps` from `next/dist/lib/metadata/metadata-resolution-primitives.d.ts` as:

```typescript
type LayoutProps = {
  children: React.ReactNode;
  params: Promise<Record<string, string | string[]>>;
  searchParams: Promise<Record<string, string | string[]>>;
};
```

It doesn't accept a route string generic. TypeScript treats `LayoutProps<"/">` as an unresolved generic rather than failing — which is why the build log shows no TypeScript error — but the type annotation is meaningless. The fix:

```typescript
export default function RootLayout({ children }: { children: React.ReactNode }) {
```

**Confidence:** confirmed — traced through `node_modules/next/dist/lib/metadata/metadata-resolution-primitives.d.ts`.
